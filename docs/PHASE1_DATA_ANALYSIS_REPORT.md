## 对 Instance-Aware 方法的影响

### ✅ 支持的发现

1. **多实体场景充足**: 42.8% (642条) 足够训练和评估
2. **2-3 实体为主**: 608条，适合初始实现和验证

### ⚠️ 需要注意的点

1. **4+ 实体样本较少**: 仅 34条 (2.3%)，复杂场景测试可能不充分
2. **单实体仍占多数**: 57.2%，需要确保 Single-entity branch 性能不降
3. **同类型实体未量化**: 需要进一步分析多个 person 或 organization 共现的情况

## 决策点 1 验证：Scene Analyzer 可行性

### 场景分类任务定义

**二分类任务**:
- **Class 0 (Single)**: 0-1 个实体 → 858 条 (57.2%)
- **Class 1 (Multi)**: 2+ 个实体 → 642 条 (42.8%)

**三分类任务**（可选）:
- **Class 0 (Empty/Single)**: 0-1 个实体 → 858 条
- **Class 1 (Multi 2-3)**: 2-3 个实体 → 608 条
- **Class 2 (Multi 4+)**: 4+ 个实体 → 34 条

**推荐**: 先实现**二分类**，样本分布均衡（57:43）

### 特征工程

可用特征：
1. **实体数量**: 直接统计（Oracle特征，仅用于验证）
2. **文本长度**: token 数量
3. **实体密度**: 实体数 / token 数
4. **类型多样性**: unique entity types
5. **命名实体密度模式**: 多个 B- 标签出现的模式

### 预期性能

基于数据分布，**简单分类器应该能达到 >90% 准确率**：
- Majority baseline: 57.2%
- 基于实体数量的规则: ~100%（但这是作弊）
- 基于文本特征的分类器: 预期 90-95%
